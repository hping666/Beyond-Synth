- 2026-09-12 · V4 (DPV) scope and guardrails (human decision, verbatim policy): V4 is enabled only for combinational modules (no clock port) and only after an inconclusive V3. Guardrail 1: V3's counterexample takes precedence: a SEQ `falsified` is final, V4 is not run and can never overturn it. Guardrail 2: a V4 `proven` is accepted only if (i) the lemmas cover every output of the module, (ii) the transaction carries no `assume` constraint, and (iii) a non-vacuity check for that module passed: at least one deliberately injected-error variant (spec 03 §3 mutants, generated by `src/equiv/mutants.py`, confirmed functionally different by lock-step simulation) is `falsified` by DPV; the record keeps `v4_status` separately and a `proven_by = seq | dpv` field; the paper reports how many proofs come from DPV. Guardrail 3: automation for clocked datapaths is decided after the Phase 2 SEQ pilot, which records (a) how many SEQ-inconclusive candidates are clocked arithmetic modules, (b) whether the per-output offsets measured by V2 are constant across all random runs, (c) whether the module has recognisable start/valid and done/valid signals; only modules meeting all three qualify for automatic phase derivation with the lemma "at phase 1 both starts are 1 and the inputs are equal ⇒ spec.out(k1) == impl.out(k2)" plus a cover proving done is reachable at k1/k2 (anti-vacuity); the rest stay inconclusive · reports/phase0.md question 6 · docs/spec/03-equivalence.md, docs/PLAN.md 2.4, src/equiv/stack.py, src/equiv/dpv.py, src/equiv/mutants.py, src/db/schema.sql (`candidates.proven_by`) · human
